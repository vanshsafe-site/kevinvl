# K.E.V.I.N — Keeping Every Voice in Need

A private, browser-only emotional-support chat. This is the React rebuild of the original vanilla-JS app.

- React 18 + Vite
- Transformers.js 4.0.1 in a Web Worker
- `HuggingFaceTB/SmolLM2-360M-Instruct` (WebGPU `q4f16`, WASM/CPU fallback `q8`)
- No backend, no API key, no model files in the repo

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # static output in dist/
npm run preview
```

Deploy `dist/` to any static host. On Vercel: import the repo, framework preset **Vite**, no environment variables.

## What's new compared with the original

**Conversations**
- Multiple conversations with a sidebar, grouped by day; saved on the device (localStorage) and restored on reload
- Delete a conversation (two-click confirm), or delete everything from Settings
- Export any conversation as Markdown
- Copy a reply, or ask for another one (regenerate)
- Stop button; stopping keeps the partial reply

**Care and safety**
- Crisis language ("I don't want to live", "hurt myself", etc.) shows a resources card next to the reply and adds a safety instruction to the model for the following messages. Nothing is blocked. Edit the resources in `src/config.js` (`CRISIS_RESOURCES`, `EMERGENCY_NUMBERS`) for your audience.
- Breathing exercise (box, 4-7-8, even) in a dialog, reachable from the header or by tapping the lantern
- "How are you arriving today?" starters that fill the message box (they don't send)

**Control**
- Reply style: gentle listener, practical friend, short and calm
- Reply length, variety (temperature) and conversation memory (how many recent messages are sent to the small model)
- Light, dark or system theme
- Optional auto-start of the model, and an option to keep chats in memory only

**Engineering**
- Worker requests carry an id, so stale tokens can't land in the wrong message
- The system prompt is built from your settings, with the owner rule kept intact
- Recent-message trimming keeps prompts inside what a 360M model handles well
- Streaming updates only re-render the message being written
- Auto-scroll pauses when you scroll up, with a "jump to latest" button
- Accessible: labelled controls, dialogs with Escape, visible focus, reduced-motion support

## SEO

A single-page chat app has little to index, so the basics are done carefully and the page still says what it is.

- **Set your public URL when building** so canonical, `og:image`, the sitemap and structured data get absolute URLs:
  `SITE_URL=https://your-domain.com npm run build` (or `VITE_SITE_URL` in `.env`). On Vercel, `VERCEL_PROJECT_PRODUCTION_URL` is picked up automatically. Without it, those tags are left out rather than pointing at the wrong place.
- `index.html`: keyword-led title (60 chars) and description (135 chars), robots, canonical, Open Graph and Twitter cards, manifest, icons.
- **Pre-rendered content** inside `#root`, so crawlers, link unfurlers and no-JS visitors see real text before React loads.
- **Structured data** (`WebApplication` and `FAQPage` JSON-LD) generated at build time from `src/faq.json`, the same file that renders the on-page "Good to know" section, so the two never drift apart.
- One `h1` (the page topic), a proper heading order, semantic landmarks and labelled controls.
- `robots.txt` and `sitemap.xml` are generated by `seo-plugin.js` during `npm run build`.
- `public/manifest.webmanifest` plus 192/512/maskable/Apple icons and a 1200×630 share image. Regenerate them with `npm run icons` after editing `scripts/generate-icons.cjs`.
- Performance (a ranking signal): the heavy model code lives in the worker and never blocks the first paint, hashed assets are cached for a year (`vercel.json` and `public/_headers`), and DNS for the model hosts is prefetched.
- Conversations never appear in URLs and stay on the device, so there is nothing private to index.

## Project layout

```
src/
  App.jsx                  wiring: chats, model, settings
  config.js                model id, system prompt, styles, crisis resources, breathing patterns
  worker/kevin.worker.js   loads the model and streams tokens
  hooks/                   useKevin (worker), useChats (storage), useLocalStorage
  lib/                     safety checks, formatting/export helpers
  components/              Sidebar, TopBar, Welcome, ModelGate, Message, Composer, Breathing, Settings
  styles.css               tokens (dark + light) and all styling
```

## Notes

- The owner answer (`K.E.V.I.N's owner is Vansh Garg.`) is answered directly in the app without calling the model.
- Crisis detection is a simple keyword check. It will miss things and occasionally over-trigger, and K.E.V.I.N is not a substitute for professional or emergency help.
- WebGPU is used when available; otherwise the app runs on WASM/CPU, which is slower. If loading fails, check your connection, disable extensions that block `huggingface.co` or `jsdelivr.net`, or clear the site's data and reload.
- Inference is local. The browser still needs network access for the first model download.
